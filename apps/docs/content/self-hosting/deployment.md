A production Finapp has three deployable parts: the **Convex backend**, the **Next.js web app** (which also hosts the MCP server) and the **mobile app**. Deploy them in that order. The web build never deploys Convex functions, so a green web deployment says nothing about the backend.

## 1. Deploy the Convex backend

Create a production Convex deployment (Convex Cloud or a self-hosted backend), set its environment variables, then deploy the schema, functions, HTTP routes, cron jobs and auth configuration from the repository root:

```bash
export CONVEX_DEPLOY_KEY='<production deploy key>'
bunx convex deploy
```

Keep the deploy key in a secret store or an untracked `.env` file, never in Git. The deploy regenerates `convex/_generated`; commit any changes so the apps build against the same API.

### Convex environment variables

Set these with `bunx convex env set NAME value` (add `--prod` when targeting production from a dev setup) or in the Convex dashboard.

| Variable                  | Required                 | Purpose                                                                                                                                                                       |
| ------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CONVEX_SITE_URL`         | Yes (provided by Convex) | Convex Auth's issuer domain; `convex/auth.config.ts` refuses to load without it                                                                                               |
| `JWT_PRIVATE_KEY`, `JWKS` | Yes                      | Convex Auth session signing keys, generated by Convex Auth's setup (`npx @convex-dev/auth`)                                                                                   |
| `AUTH_RESEND_KEY`         | Yes                      | Resend API key for verification, password-reset, two-factor and app-lock reset emails. Sign-up requires email verification.                                                   |
| `AUTH_EMAIL_FROM`         | Recommended              | Sender address, default `Finapp <onboarding@resend.dev>`                                                                                                                      |
| `GEMINI_API_KEY`          | For AI                   | FinAI's built-in model and receipt scanning. Without it, users can still run FinAI on their own keys if `AI_KEYS_SECRET` is set.                                              |
| `AI_KEYS_SECRET`          | For BYOK and 2FA         | 32 random bytes, base64. Encrypts users' own AI provider keys and authenticator-app secrets (AES-256-GCM). Without it, BYOK and authenticator-app two-factor are unavailable. |
| `EXPO_ACCESS_TOKEN`       | Optional                 | Authenticates requests to the Expo push service                                                                                                                               |
| `MCP_ISSUER_URL`          | For MCP                  | The web app's canonical HTTPS origin; enables the MCP backend JWT provider. See [Deploying the MCP server](/mcp/deployment).                                                  |
| `PUBLIC_API_IP_SALT`      | For the public API       | 32 random bytes, base64                                                                                                                                                       |
| `WEBHOOK_SECRET_KEY`      | For the public API       | 32 random bytes, base64                                                                                                                                                       |

Generate the random values with:

```bash
openssl rand -base64 32
```

:::warning
Don't change `AI_KEYS_SECRET` once users have saved keys or set up an authenticator app. Stored values are bound to the secret and can't be decrypted with a new one.
:::

### Public REST API

The Convex deployment serves a public REST API at `/api/v1` on its **site URL** (`https://<deployment>.convex.site/api/v1` on Convex Cloud). The web app also forwards `/api/v1/*` on its own domain to that URL. See the [developer docs](/developers/overview) for authentication, endpoints and webhooks.

| Variable                  | Where             | Purpose                                                                                                                                                              |
| ------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WEBHOOK_SECRET_KEY`      | Convex            | 32+ random bytes, base64. Webhook signing secrets are derived from it; without it, creating webhooks returns `503`. Changing it invalidates every endpoint's secret. |
| `PUBLIC_API_IP_SALT`      | Convex            | Any random string. Used to fingerprint callers' IPs ("last used from"); without it no fingerprint is recorded.                                                       |
| `PUBLIC_API_URL`          | Convex (optional) | Public origin written into `/api/v1/openapi.json` (defaults to `CONVEX_SITE_URL`).                                                                                   |
| `MCP_ISSUER_URL`          | Convex (optional) | The web app's origin, used for the OAuth URLs in the OpenAPI document.                                                                                               |
| `FINAPP_API_UPSTREAM_URL` | Web (optional)    | Where the web app's `/api/v1` proxy forwards. Defaults to `CONVEX_SITE_URL`, or the `.convex.site` twin of `NEXT_PUBLIC_CONVEX_URL`. Set it for self-hosted Convex.  |
| `NEXT_PUBLIC_DOCS_URL`    | Web (optional)    | The docs site, linked from Settings → API & developer.                                                                                                               |

Generate the key with `openssl rand -base64 32` and set it with `bunx convex env set WEBHOOK_SECRET_KEY …`.

### Scheduled jobs

`convex/crons.ts` is deployed with the functions and needs no extra setup:

- daily at 03:15 UTC: delete Trash items past each user's retention;
- hourly: delete FinAI attachment files past their retention;
- hourly: public API housekeeping (expired idempotency keys and OAuth codes, idle rate-limit buckets, developer activity and webhook delivery logs older than 30 days).

## 2. Deploy the web app

The web app is a standard Next.js app in `apps/web`. It is built from the monorepo root because it imports `packages/ui`, `packages/widgets`, `packages/mcp` and the generated Convex API.

### Web environment variables

| Variable                                            | Required | Purpose                                                                         |
| --------------------------------------------------- | -------- | ------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_CONVEX_URL`                            | Yes      | The production Convex URL. Inlined at build time, so rebuild after changing it. |
| `MCP_ISSUER_URL`                                    | For MCP  | Canonical HTTPS origin of the web app                                           |
| `MCP_RESOURCE_URL`                                  | For MCP  | `https://<web-origin>/mcp` (defaults to `/mcp` on the issuer)                   |
| `MCP_SIGNING_KEY_ID`                                | For MCP  | Stable key ID published in the JWKS                                             |
| `MCP_SIGNING_PRIVATE_KEY`, `MCP_SIGNING_PUBLIC_KEY` | For MCP  | Matching RSA key pair (PKCS#8 private, SPKI public, at least 2048 bits)         |
| `MCP_ALLOWED_ORIGINS`                               | Optional | Extra browser origins allowed to call `/mcp`                                    |
| `OPENAI_APPS_CHALLENGE_TOKEN`                       | Optional | ChatGPT app domain verification                                                 |

Key generation, deployment order for MCP and the verification checklist are in [Deploying the MCP server](/mcp/deployment).

### Deploying on Vercel

The reference deployment uses Vercel with the project's **root directory** set to `apps/web`:

```bash
vercel deploy --prod
```

Run it from the repository root. The committed `.vercelignore` excludes local agent folders and the mobile native projects; Vercel reads only that file when it exists, so keep it in sync with `.gitignore`. With the GitHub integration, merging to `main` also triggers a production build.

Any host that can run `next build` and `next start` for a Bun workspace works the same way. After deploying, make sure `/.well-known/*` and `/mcp` are publicly reachable and not behind deployment protection.

## 3. Build the mobile app

The mobile app is built with EAS. `apps/mobile/eas.json` defines a `production` profile (Android APK, internal distribution, update channel `production`) plus per-architecture variants: `production-arm64-v8a`, `production-armeabi-v7a`, `production-x86_64` and `production-x86`.

Each profile sets the backend the app talks to:

```json
"env": {
  "EXPO_PUBLIC_CONVEX_URL": "https://<deployment>.convex.cloud",
  "EXPO_PUBLIC_CONVEX_SITE_URL": "https://<deployment>.convex.site",
  "EXPO_PUBLIC_APP_ENV": "production"
}
```

:::warning
The committed `eas.json` points at the maintainers' production deployment. Change these values to your own deployment before building.
:::

Build from `apps/mobile`:

```bash
bunx eas-cli@latest build --platform android --profile production
```

### Over-the-air updates

Native builds include `expo-updates` with the app-version runtime. Publish JavaScript and asset changes that are compatible with the installed native code:

```bash
npx eas-cli@latest update --channel production --environment production --message "<message>"
```

### Android release workflow

`.github/workflows/android-release.yml` builds the universal APK and the four per-architecture APKs on EAS and attaches them, with `SHA256SUMS.txt`, to the product's GitHub release. It runs only when started manually and needs an `EXPO_TOKEN` repository secret.

## Versions and releases

`version.json` is the only hand-edited version source. It holds the product version and the web, mobile, UI and backend component versions plus mobile build numbers.

```bash
bunx changeset                       # in a PR: describe package changes
bun run version:bump backend minor   # backend changes (not a workspace package)
bun run version:release              # apply changesets and regenerate derived files
bun run version:bump product minor   # name the product release
```

When `version.json` changes on `main`, the **Release** workflow tags `finapp-v…`, `web-v…`, `mobile-v…`, `ui-v…` and `backend-v…` and publishes a GitHub release with notes built from the changelogs and the tagged `version.json` attached.

The backend also declares the **minimum supported** web and mobile versions in `convex/shared/version.ts`. After a backend deploy that raises them, older mobile builds show an _update required_ notice.

## After deploying

1. `GET https://<deployment>.convex.site/version` returns the running backend's product and component versions.
2. Sign up with a new account and confirm the verification email arrives.
3. Open the web app, add a transaction, and check it appears on a second device.
4. If you enabled AI, send FinAI a message and scan a receipt.
5. If you enabled MCP, follow the [MCP verification checklist](/mcp/deployment#verifying-a-deployment).
